# CCN Experiment 1

一个用于数据链路层实验的 Python 小项目，实现了简单数据帧的封装、CRC 校验、解包，以及 ACK/REJ 控制帧的构造。当前程序通过控制台输入和输出演示帧格式，**不会通过网络发送或接收数据**。

## 功能

- 使用 IPv4 地址字段构造数据帧。
- 将数据负载按 GBK 编码/解码。
- 计算并校验帧校验字段。
- 构造数据帧、ACK 应答帧和 REJ 拒绝帧。
- 将输入的二进制字符串转换为字节，并从输入数据中截取帧。

## 环境要求

- Python 3.10 或更高版本（`main.py` 使用了 `match` 语句）。
- NumPy（项目模块导入时需要）。

安装依赖：

```bash
python -m pip install numpy
```

仓库中的 `require.txt` 是实验设计和流程说明，并不是 pip 依赖清单。

## 运行

在项目目录中执行：

```bash
python main.py
```

程序会提示输入要发送的文本，将文本编码为 GBK 后尝试按每段最多 24 字节分帧，并打印帧的二进制形式和字节内容。发送端使用的目的地址和源地址目前写在 `main.py` 中。注意：当前主程序在每段后多推进了一个字节，超过 24 字节的文本可能会漏掉分段边界处的数据。

完成发送演示后，程序会提示输入二进制数据作为接收数据，并尝试截取和解包其中的帧。输入应只包含 `0` 和 `1`，且表示完整帧；当前转换逻辑会丢失开头的零字节，因此带有前导零的帧可能无法正确还原。

## 帧格式

| 字段        |   长度 | 说明                             |
| ----------- | -----: | -------------------------------- |
| 起始标志    | 1 字节 | `0x7E`                         |
| 目的地址    | 4 字节 | IPv4 地址                        |
| 源地址      | 4 字节 | IPv4 地址                        |
| 数据长度    | 1 字节 | 数据负载的字节数                 |
| 数据负载    |   可变 | 数据帧使用 GBK 编码              |
| 帧类型/序号 | 1 字节 | 高 4 位表示类型，低 4 位表示序号 |
| 校验字段    | 2 字节 | 对前面的帧内容计算               |
| 结束标志    | 1 字节 | `0x7E`                         |

帧类型高 4 位：`0x1` 为数据帧，`0x2` 为 ACK，`0x3` 为 REJ。代码使用 `zlib.crc32` 计算 CRC-32 后截取低 16 位作为两字节校验字段；这不是标准 CRC-16 算法。

## 模块说明

- `Framing_Function.py`：数据帧、ACK 和 REJ 的构造，以及校验字段计算。
- `Unpacking_Function.py`：二进制输入、CRC 校验和帧解包。
- `BinToInt.py`：二进制字符串转整数。
- `main.py`：控制台演示入口。
- `require.txt`：实验设计笔记。

## 在代码中使用

```python
import Framing_Function
import Unpacking_Function

frame = Framing_Function.Framing_Function1(
    "hello".encode("gbk"),
    destinationaddress="192.168.30.102",
    sourceaddress="192.168.30.110",
    times=1,
)

print(Unpacking_Function.Unpacking_Function1(frame))
# ('hello', 1)
```

## 当前限制

- `main.py` 在模块顶层直接执行交互逻辑；运行它会等待控制台输入。
- 地址目前是硬编码的，`socket` 仅用于将 IPv4 地址转换为 4 字节字段，并未创建网络连接。
- 24 字节分段是主程序的行为，帧封装函数本身没有强制限制负载长度。
- 序号保存在帧类型的低 4 位，接收端只读取这 4 位；序号超出 `0`–`15` 时不保证正常工作。
- 当前接收输入按整数转换，不能保留前导零字节；帧截取和错误处理也仅适用于实验演示。
